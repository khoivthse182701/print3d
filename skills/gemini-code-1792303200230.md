# Automated Code Review & Evaluation Skill

Use this skill whenever the user asks to review code, audit a pull request, evaluate a file/module, or check code quality before merging.

## 1. The 5-Pillar Inspection Checklist

Every code review MUST systematically audit the target code against these 5 dimensions:

1. **Architecture & SOLID Compliance:**
   - Are layer boundaries respected (e.g., Controller directly calling `DbContext`, UI component executing raw business rules)?
   - Does any class violate Single Responsibility (God object) or Dependency Inversion?
2. **Performance & Resource Management:**
   - **Database / ORM:** Detect `N+1` queries inside loops, missing `.AsNoTracking()` on read-only queries, loading full tables into memory before filtering (`ToList()` before `Where()`), or missing pagination.
   - **Async / Memory:** Detect sync-over-async deadlocks (`.Result`, `.Wait()`), missing `CancellationToken` propagation, un-disposed streams/connections, or heavy allocations inside 60fps `Update()` loops (in Unity/Blender scripts).
3. **Security & Data Integrity (OWASP):**
   - SQL Injection, raw string interpolation in queries, Mass Assignment (binding domain entities directly to HTTP requests), missing authorization/ownership checks (IDOR), or sensitive data logged in plain text.
4. **Correctness, Edge Cases & Concurrency:**
   - Null reference risks, off-by-one errors, floating-point money calculations (`double`/`float` used instead of `decimal`), race conditions on shared state, or swallowed exceptions (`catch (Exception) {}`).
5. **Readability & Maintainability:**
   - Naming clarity, magic numbers/hardcoded values, dead commented-out code, and cyclomatic complexity.
