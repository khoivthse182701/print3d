# Workspace & Architecture Folder Organizer Skill

Use this skill whenever the user asks to organize project folders, clean up a messy repository, structure a new solution, or move misplaced files into their proper architectural layer.

## 1. Golden Rules of Directory Organization

1. **Screaming Architecture (Layer + Feature Slice):**
   - Top-level folders represent **Architectural Layers** (`Domain`, `Application`, `Infrastructure`, `Presentation`), and second-level folders inside `Application` and `Presentation` group files by **Business Feature / Aggregate** (`Orders`, `Users`, `StorageUnits`, `Payments`) rather than dumping 200 unrelated files into a single generic `Services/` or `DTOs/` folder.
2. **One Primary Type Per File:**
   - Every class, interface, enum, or component must live in its own file whose filename matches the type name (`ReserveUnitCommandHandler.cs`, `StorageUnitCard.tsx`).
3. **Namespace & Import Parity:**
   - Whenever moving a file to a new folder, ALWAYS update its `namespace` (C#), module imports (TypeScript/React), or package path (Python) and fix all project references.
4. **Zero Root Clutter:**
   - Only solution configuration files (`.sln`, `README.md`, `.gitignore`, `docker-compose.yml`, `Directory.Build.props`) belong at the repository root. Scripts go to `/scripts`, documentation to `/docs`, and tests to `/tests`.

## 2. Canonical Directory Blueprints

### A. Backend (.NET / Clean Architecture + CQRS)
```text
├── docs/                                # Architecture diagrams, API specs, ADRs
├── scripts/                             # SQL migrations, seeders, automation scripts
├── src/
│   ├── Project.Domain/
│   │   ├── Common/                      # BaseEntity, ValueObject, IDomainEvent, Result<T>
│   │   ├── Constants/                   # Domain-wide constants & roles
│   │   ├── Entities/                    # Rich Domain Entities
│   │   ├── Enums/                       # Strongly-typed domain enums
│   │   ├── Events/                      # Domain Event definitions
│   │   ├── Exceptions/                  # Domain-specific exceptions
│   │   └── ValueObjects/                # Money, Address, DateRange
│   │
│   ├── Project.Application/
│   │   ├── Common/
│   │   │   ├── Behaviors/               # Validation, Logging, Transaction pipelines
│   │   │   ├── Interfaces/              # IUnitOfWork, IRepository, External service contracts
│   │   │   └── Mappings/                # Mapper profiles / projection extensions
│   │   └── Features/
│   │       └── <FeatureName>/           # e.g., StorageUnits, Bookings, Payments
│   │           ├── Commands/
│   │           │   └── <ActionName>/    # Command.cs, CommandHandler.cs, CommandValidator.cs
│   │           ├── Queries/
│   │           │   └── <QueryName>/     # Query.cs, QueryHandler.cs, ResponseDto.cs
│   │           └── EventHandlers/
│   │
│   ├── Project.Infrastructure/
│   │   ├── Data/
│   │   │   ├── Configurations/          # IEntityTypeConfiguration<T> per entity
│   │   │   ├── Migrations/              # EF Core auto-generated migrations
│   │   │   ├── Repositories/            # Concrete repository implementations
│   │   │   └── ApplicationDbContext.cs
│   │   ├── Identity/                    # JWT, Auth services
│   │   ├── Services/                    # Email, Cloud Storage, Payment Gateways
│   │   └── DependencyInjection.cs
│   │
│   └── Project.WebAPI/
│       ├── Controllers/                 # Thin REST controllers grouped by resource
│       ├── Middlewares/                 # GlobalExceptionHandler, Auth middleware
│       ├── Extensions/                  # ServiceCollection & WebApplication extensions
│       ├── Program.cs
│       └── appsettings.json
│
└── tests/
    ├── Project.Domain.UnitTests/
    ├── Project.Application.UnitTests/
    └── Project.WebAPI.IntegrationTests/
```

### B. Frontend (React / TypeScript Feature-Sliced Structure)
```text
src/
├── app/                                 # App router, global providers, store setup
├── assets/                              # Static fonts, icons, global CSS
├── components/
│   └── ui/                              # Reusable atomic UI primitives (Button, Modal, Table)
├── features/
│   └── <feature-name>/                  # e.g., auth, bookings, dashboard
│       ├── api/                         # Endpoints & React Query hooks
│       ├── components/                  # Feature-specific UI components
│       ├── hooks/                       # Feature-specific state logic
│       ├── types/                       # TypeScript interfaces/DTOs for this feature
│       └── index.ts                     # Public barrel export
├── hooks/                               # Shared global custom hooks
├── lib/                                 # Axios client, utilities, formatters
└── types/                               # Shared global types
```

### C. 3D / Game Project (Unity / Blender Pipeline)
```text
Assets/ (or ProjectRoot/)
├── _Project/                            # Isolate custom project assets from third-party plugins
│   ├── Art/
│   │   ├── Characters/<CharName>/       # Models, Textures, Materials, Rig, Animations
│   │   ├── Environment/
│   │   └── Shaders/
│   ├── Audio/                           # BGM, SFX
│   ├── Prefabs/                         # Characters, Environment, UI
│   ├── Scenes/                          # Main, Sandbox, Levels
│   ├── Scripts/
│   │   ├── Core/                        # Managers, Singleton, EventBus
│   │   ├── Gameplay/                    # PlayerController, Physics, Combat
│   │   ├── ScriptableObjects/           # Data configs (zero hardcode)
│   │   └── UI/
│   └── Settings/                        # Render Pipeline, Input Actions
└── ThirdParty/                          # External packages/plugins
```

## 3. Execution Protocol When Reorganizing a Project

1. **Scan & Map:** List all current files and identify misplaced files, duplicate utilities, or God folders.
2. **Propose Migration Table:** Show a clear `Old Path -> New Path` table before moving destructive paths, or execute directly if requested.
3. **Safe Move & Refactor:**
   - Use `git mv` (if in a Git repo) to preserve commit history.
   - Update all `namespace` declarations, `using` statements, `import` paths, and `.csproj` references.
4. **Verify Build:** Run `dotnet build` / `npm run build` immediately after restructuring to guarantee zero broken references.
